# Travel in the Second World

发布基线：1.1.1。使用通用设计流程，按宿主实际能力选择绘图与导出工具；不绑定 Agent 平台、模型厂商或订阅。

## 能力选择

先确认宿主是否能读取原照片、查看生成结果，并调用支持参考图或局部编辑的绘图工具。使用当前可用且获授权的模型；不要因为缺少某个厂商的 Key 就停止通用设计流程。仅能文生图的工具不能可靠保留原片，须说明限制。宿主不能安装 Skill 时直接读取本文件及按需参考，作为当前任务的工作指南。

- **静态海报**：使用宿主图像编辑能力。Python、命令行和特定接口凭据均不是通用出图的前置条件。需要精确保留时采用宿主可用的局部编辑、蒙版或文件合成；无法验证像素保留时不得承诺无损。
- **三秒视频**：仅在有文件执行能力或已接通视频生成工具时制作。附带本地水纹脚本需要 Python 3.10+、Pillow、NumPy、SciPy、ffmpeg 与 ffprobe；先用 `run.py` 的 `status` 诊断，不静默安装。其 `ready`、`poster_ready` 只诊断附带脚本与可选接口，不代表宿主绘图能力。
- **可选工具**：需要精确裁切预览、离线选区或选择绘图路线时读 [工具选择与输入契约](references/providers.md)。仅在明确选用附带测试接口时读 [可选图片服务适配器](references/optional-image-service.md)，按其协议配置；不能把接口兼容或更换模型名当作所有模型均已适配。
- 将任务输出放在独立工作目录，禁止写入安装包。凭据按宿主安全配置方式提供，不写入聊天、JSON、提示词或输出文件。涉及外部服务时说明照片会发送到所选服务及可能消耗额度，在已有授权内执行，不重复确认。

## 默认成品

- 将每张原照片视为独立来源；只借鉴参考图手法，绝不混合不同照片或复制参考内容。
- 使用宽:高 **3:4** 的完整竖幅，不制作样机或九宫格。将“4:3 竖幅”解释为高:宽 4:3。
- 将照片与纸上世界的视觉占比设为约 **60:40**，通常控制在照片 55–65%、纸上世界 35–45%。允许沿结构局部穿越，避免强行直切或统一撕纸边。
- 默认交付一张 PNG 和一个 **恰好 3 秒**的 MP4；只要求静态图时仅交付 PNG。将 MP4 视为后续转换 Live Photo 的素材，不能把 MP4 或 GIF 宣称为原生 Live Photo。
- 使用中文角落小字，不自动添加英文、巨大标题、徽标或水印。优先执行用户最新的比例、文案、编辑权限和交付要求。

## 1. 读图、规划和查证

1. 读取实际文件、方向及像素尺寸；明确原图、参考图和当前批准版本。文件缺失时查找已知附件或对应保存文件，不拿缩略图冒充原片。
2. 批量任务先为各图列出原尺寸、主体、裁切、连接结构和独立互动，再按授权顺序推进。用户只要求统筹时先规划，不提前出图；已授权继续时完成工作，不用进度回复代替执行。
3. 选择自然到达照片下缘的真实结构：水面、河岸、道路、阶梯、岩层、树枝、衣物或人物动作。记录交点、方向、宽度、尺度、透视和遮挡。
4. 等比缩放并优先裁掉空天空、重复前景或偶然入镜的残肢。通常尝试裁切不超过原面积约 15%，竖图必要时约 20%；将这些作为参考，不能为了比例裁掉关键主体或连接结构。冲突时保留主体并说明实际取舍，不能暗中重绘重要结构规避约束。
5. 核对地点的省级及地级行政区、景点含义和文案出处，优先使用政府、景区官方、可靠学术机构或原始诗文。不能从相似风景猜具体地点；无法确认时只写已知地名。正确区分自治州、地区和地级市。
6. 优先采用用户指定句子；其次选择已核实的贴景诗句或简短地方说明；再考虑围绕具体互动的克制原创旁注。如实区分引用与原创，不杜撰人物约定、作者、出处或名句。查不到合适文案时写地名即可。

## 2. 生成连续的纸上世界

先阅读 [设计与修图细则](references/design-and-edits.md)。

1. 使用当前 Agent 可用的图像编辑工具。先看原片与裁切方案，明确原片、参考图的角色及不可改区域；将准确连接交点和单一互动写入工具的编辑指令，不把同一套参数强套给不同模型。需要本地裁切预览时才执行 `prepare`；附带 `poster` 动作仅服务于可选适配器。
2. 先接通源结构，再改变物理规则。只做 **一种转化、一个互动**；不要从固定道具反推每张图，也不要重画下方整片风景。
3. 使用温暖象牙色纤维纸、大面积留白、少量原材质片段与细黑线。将视觉顺序保持为原照片及连接结构、互动、角落小字。
4. 必要时加入 0–3 个微小人物，通常一个即可。检查手与物体、脚与地面、臀部与承托面的准确接触和受力。默认把看河的人放在干燥岸边，臀部与双脚落地，与水面留出可见距离；不要让纸上河流承担人体重量。
5. 保留照片身份、主体数量、比例、空间关系和重要细节。上方照片默认直接复用原像素；只有用户允许时才做适度氛围编辑。不能把生成式重绘或重采样称为“无损保留”。
6. 在原分辨率画布中复用需要保留的源像素，按准确几何位置接入生成区域。只在对齐的局部接缝做小范围柔和过渡。出现双岸线、重影树木或漂浮建筑时重新对齐，不扩大模糊区掩盖错误。
7. 将文字放在自然留白处，保持自然略潦草但清楚可读的手写和较小字号。不要遮挡连接点与互动，不用乱码模拟手写。

## 3. 局部修改已批准作品

1. 将当前批准成品作为编辑目标，备份它并保留已有文件身份。
2. 仅修改用户要求的区域和因素，例如“坐在水中”改为“坐在干燥岸边”；修复原位置的水面和岸线，不残留旧人物。
3. 查看生成输出，重新确认变化范围，在原分辨率上将局部结果接入批准成品；编辑区外复用原成品像素，尤其保护原照和正确文字。
4. 用像素差检查承诺不变的区域，再目视检查边界、人物支撑及文案。不能仅依赖模型的“保持不变”承诺。
5. 同步更新本图视频和运动区域，去掉旧人物位置的位移场；不要误更新其他照片或保留过期动画。

## 4. 制作三秒局部动画

先确认视频能力。使用附带本地水纹路线时阅读 [动画参数与执行](references/motion.md)，从 Skill 根目录运行 `python3 run.py`，通过 stdin JSON 调用 `animate`；没有遮罩时执行 `select_motion`，由用户或具备浏览器能力的助手圈选水面、扣除遮挡并画流向。使用宿主已接通的视频工具时沿用以下保护与验收规则，并如实记录所用方式；本包没有自动接入任意视频模型。没有视频能力时完成静态图，明确三秒视频尚未制作，不交付静止视频充数。

- 附带脚本采用二维局部动画，24 fps、72 帧、无声 H.264 MP4；如实说明方法，不暗称为视频模型生成。其他可用视频工具导出后核对恰好三秒，必要时转码并保护静止区域。
- 先确定一个手机尺寸下可辨认的主动态：沿河道流动的水纹、明确卷动的纸边、受约束的手臂动作等；轻微呼吸和光影仅作辅助，不能单独冒充动态成品。根据实际成品设置运动区域，保持文字、主体结构和支撑点稳定；坐在岸上的人不随水面漂动。
- 连续覆盖整个三秒，不拼接断裂动作，不用整图推拉、平移或缩放代替局部运动。优先保证自然方向与清楚可见；Live Photo 不要求视频无缝循环，不能为了循环让河流来回倒流。仅在自然适合时使用周期运动。
- 每帧从同一原始成品采样，避免累计模糊。水面优先按真实河道方向搬运纹理并固定岸线；脚本的波形位移仅适用于纹理摆动。走路、卷纸、折船、手臂或转身动作采用分层及关节约束，不能把整个人物轻晃称为完成动作。需要完整动作而工具只能微动时如实说明限制，不交付假动作。
- 水面与树林、阴影、建筑或人物同框时，不能只用颜色识别水。按真实河岸建立显式水面遮罩，并保护遮在水前的枝叶；运动和取样均不得越出该范围。用户要求“只动水”时关闭人物、树林、光影的辅助运动。逐帧确认遮罩外原始像素不变，再检查编码后树林和岸线有无实际位移。
- 持续观察已启动任务直至完成，维护简短进度；不能在工具仍运行或文件未完成时宣称交付。

## 5. 验收与交付

1. 完整打开 PNG，核对 3:4、分辨率、视觉占比、源片质量、单一互动、留白和中文可读性。
2. 逐一检查连接交点、岸线或道路宽度、遮挡层级、手脚及臀部支撑，排除重影、悬浮、重复人物和残留旧动作。
3. 视频可用时核对尺寸、3 秒、无音轨及完整解码；附带脚本输出还须核对 24 fps、72 帧，可通过 `run.py` 的 `check_pair` 与 `audit_motion` 检查。按 390×520 手机尺寸检查 0、0.75、1.5、2.25、接近 3 秒的全图及放大图；主动作应直接可辨认，岸线、文字和支撑点稳定。仅有非零帧差、编码噪声、曝光变化或小于一个屏幕像素的晃动不算验收通过。
4. 局部修改时用可用的像素比较工具校验保护区域；使用附带脚本时在 `check_pair` JSON 中传入 `before` 与 `unchanged_boxes`，坐标按原分辨率像素填写。
5. 按当前能力保存成品。修改已有保存文件时沿用身份及版本，不制造多个“最终版”。保存及检查成功后，每张仅返回一张最终图片和一个三秒视频；仅要求静态或视频能力不可用时只返回最终图片并说明情况。隐藏中间图、运动遮罩和 QA 图。
6. 无法精确保留、未完成导出或无法确认来源时说明具体限制，不以“完全达标”替代检查。
